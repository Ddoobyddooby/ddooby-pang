# 화면 배치 설계 (W2-10a)

> 상태: 승인됨 (2026-10-30, A안) · 관련 태스크: W2-10a, W2-11, W2-12 · 시안: `docs/superpowers/specs/mocks/layout.html`

## 1. 문제

720×1280(9:16) 고정 + `FIT`라서 요즘 휴대폰(390×844, 약 9:19.5)에서는 보드 아래 약 1/3이 빈 하늘로 남는다 (2026-10-30 휴대폰 캡처). 점수·시간·미션·일시정지가 들어갈 자리도 정해지지 않았다.

## 2. 결정: A안 "아래 정보 패널"

| 항목 | 결정 | 고려한 대안 |
|---|---|---|
| 구역 | 위 **타이틀** → 가운데 **보드** → 보드 바로 아래 **정보 패널** → 맨 아래 **디저트 언덕 장식** | B: 정보는 위, 아래는 장식만 / C: 위 점수 + 아래 큰 시간 막대 |
| 정보 패널 | 보드와 같은 폭의 웨이퍼 패널. 왼쪽에 점수(크게) + 남은 시간(글자 + 솜사탕 막대). 오른쪽 열은 일시정지(W4-04)·미션(W3-10) **자리만** 비워 둔다 (지금은 그리지 않음) | |
| 마지막 10초 | 시간 글자·막대가 빨갛게 바뀌고 1초마다 살짝 통통 튄다 (`TIMEATTACK.warnMs`) | |
| 바닥 장식 | 분홍·크림 언덕 두 겹 + 막대사탕·컵케이크. 화면 맨 아래에 붙는다 | |
| 기존 정보 알약 | 없앤다 (`seed · 이동` 표시와 그 안의 `·` 문제도 함께 사라짐). 개발 모드에서만 패널 구석에 작게 `seed N` | |

## 3. 화면 길이가 다를 때

- 게임 폭은 720으로 고정하고 **높이는 화면 비율에 맞춰 늘린다**: `Phaser.Scale.EXPAND` (기준 720×1280, 더 긴 화면이면 높이만 커진다. 390×844 → 약 720×1558)
- 늘어난 높이 `extra = 높이 - 1280`은 **30%를 타이틀과 보드 사이**, **70%를 패널과 바닥 장식 사이**에 준다. 덜 긴 화면(태블릿 등)은 1280으로 FIT
- 배치는 순수 함수 `screenLayout(height): { titleY, board: {x, y, size}, panel: {x, y, w, h}, decorY }`로 계산하고 테스트한다 (`src/view/layout.ts`). 값(여백, 패널 높이, 비율)은 `config.VIEW.screen`
- 기준 1280일 때: 타이틀 y 90, 보드 y 170 (680), 패널 y 870 (높이 170), 장식은 화면 아래 220px
- **안전 영역**: `index.html`이 이미 `viewport-fit=cover`. `#game`에 `padding: env(safe-area-inset-top) … env(safe-area-inset-bottom)`을 줘서 캔버스가 노치·홈 바를 피한다. 하늘 그라데이션은 `html`에 있어 그 뒤까지 이어진다 (Capacitor WebView도 같은 규칙)

## 4. 결과 화면 (W2-12)

- `ResultScene`: 반투명 크림 판 위에 "끝!" + 점수 + 최고 점수(`newBest`면 "최고 기록!" 배지) + [다시하기]
- `GameScene`은 재생이 끝난 뒤 `mode.isOver()`면 `scene.start('Result', { result: mode.result() })`. 결과 화면은 모드를 모르고 `ModeResult`만 받는다 (스토리 결과는 W3-11에서 같은 씬에 분기 추가)
- 배치는 `this.scale.width/height` 기준 가운데 정렬 (EXPAND 높이에 맞춤)
