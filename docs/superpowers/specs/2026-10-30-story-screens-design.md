# 스토리 화면 설계 (W3-08 ~ W3-12)

> 상태: 승인됨 (2026-10-30, 메뉴 A + 지도 A) · 시안: `docs/superpowers/specs/mocks/menu-map.html` · 관련: PLAN 6.4

## 1. 화면 흐름

```
Boot ─┬─ (기본) Menu ─┬─ [스토리] StageMap ── 스테이지 탭 ── Game(story, N) ── Result
      │               └─ [경쟁 60초] ──────────────────────── Game(timeattack) ── Result
      ├─ ?stage=N (개발) ─ Game(story, N)
      ├─ ?demo / ?seed / ?time / ?specials ─ Game(timeattack)   (지금까지의 개발 주소 그대로)
      └─ ?result=… (개발) ─ Result 미리보기
```

| 씬 키 | 받는 데이터 | 버튼 |
|---|---|---|
| `Menu` | 없음 | [스토리] → `StageMap`, [경쟁 60초] → `Game { mode: 'timeattack' }` |
| `StageMap` | 없음 | 열린 스테이지 → `Game { mode: 'story', stageId }`, 잠긴 스테이지 → 좌우로 흔들림, [←] → `Menu` |
| `Game` | `{ mode: 'timeattack' } \| { mode: 'story'; stageId: number }` (없으면 timeattack) | 게임 중 나가기 버튼은 W4-04(일시정지) |
| `Result` | `{ result: ModeResult }` | 아래 4절 |

- 저장 데이터(`saveRegistry`)와 스테이지(`stageRegistry`)는 Boot가 한 번 읽어 둔 것을 모든 씬이 같이 쓴다
- 씬 사이를 오갈 때 이전 씬의 트윈·입력이 남지 않아야 한다 (`scene.start`가 이전 씬을 끈다)

## 2. 메뉴 (W3-08, A안)

- 타이틀 `Ddooby-Pang` + 그 아래 말랑 친구들 5개(블록 텍스처 `normal` 얼굴)가 번갈아 통통 튐
- 큰 웨이퍼 버튼 두 개, 버튼 안에 작은 글씨로 진행 상황
  - 스토리: `스테이지 3 / 10 ★ 5` (열린 스테이지 수 / 전체, 모은 별 합계. 가운뎃점 대신 띄어쓰기)
  - 경쟁 60초: `최고 12,450점` (기록 없으면 `처음 도전!`)
- 버튼은 누르면 말랑하게 눌린 뒤 이동 (ResultScene의 [다시하기]와 같은 버튼을 공통 컴포넌트로 뺀다: `src/view/ui/Button.ts`)
- 바닥 언덕 장식(Hills) 재사용

## 3. 스테이지 지도 (W3-09, A안)

- 아래(1번)에서 위(10번)로 구불구불 올라가는 사탕 길(흰 점선) 위에 동그라미 노드 10개. 한 화면에 다 들어간다 (스크롤 없음)
- 노드 위치는 순수 함수 `mapNodes(count, height)`로 계산하고 테스트 (화면 안, 겹치지 않음, 아래→위 순서). 값은 config
- 상태 3가지: **완료**(분홍 + 아래 별 ★☆☆), **지금 할 곳**(= 열린 것 중 가장 높은 번호, 더 진한 분홍 + 크게 + 천천히 숨쉬듯 커졌다 작아짐), **잠김**(회보라 + 자물쇠, 누르면 흔들림)
- 왼쪽 위 [←] 동그란 버튼 → 메뉴, 위쪽 제목 `스토리`
- 스테이지가 10개보다 많아지면(v0.2) 스크롤을 붙인다. 지금은 10개 고정 가정, 넘으면 개발 모드 경고

## 4. 결과 화면 (W3-11)

| | 경쟁 | 스토리 클리어 | 스토리 실패 |
|---|---|---|---|
| 제목 | `끝!` | `클리어!` | `아쉬워요` |
| 별 | 없음 | 별 3칸, 받은 만큼 하나씩 차오름(0.25초 간격, 통통) | 빈 별 3칸 |
| 점수 | 점수, 최고 점수, 새 기록 배지 (지금과 같음) | 점수 + `남은 이동 보너스 +900` (보너스 0이면 줄 없음) | 점수 |
| 버튼 | [다시하기] [메뉴] | [다음 스테이지] [다시하기] [지도] | [다시하기] [지도] |

- [다음 스테이지]는 다음 번호가 있고 열려 있을 때만 (10번 클리어면 대신 `모든 스테이지 클리어!` 한 줄)
- 스토리에서 메뉴 대신 **지도**로 돌아간다 (다음에 할 스테이지를 바로 고를 수 있게). SPEC 7절의 [메뉴]를 이렇게 바꾼다
- 개발 미리보기 확장: `?result=3200&stage=2&stars=2&bonus=900` (stage가 있으면 스토리, `stars=0`이면 실패)

## 5. 스토리 HUD (W3-10)

- 아래 웨이퍼 패널(W2-11)을 그대로 쓰고 내용만 바꾼다. `Hud`가 모드 종류에 따라 두 가지 모양을 가진다
- **오른쪽 열**(비워 둔 170px): 남은 이동. 동그란 크림 배지 안에 큰 숫자 + 아래 `이동`. 남은 이동 5 이하면 빨강 + 이동할 때마다 통통 (타임어택 10초 강조와 같은 방식, 기준값 config)
- **왼쪽**: 미션 줄(최대 2줄) + 작은 점수 줄
  - 점수 미션: `점수 1,200 / 2,000`
  - 색 수집: 그 색 블록 작은 그림(텍스처 `normal`) + `12 / 25`
  - 달성하면 그 줄 끝에 체크(✓ 대신 코드로 그린 체크 또는 Jua에 있는 글자) + 한 번 통통
  - 점수 미션이 없는 스테이지는 마지막 줄에 `점수 1,200`
- DEV `seed N`은 그대로 패널 구석

## 6. 저장·해금 (W3-12)

- 스토리가 끝나면 `recordStory(save, stageId, { cleared, stars, score })` → `commitSave` (기다리지 않음) → Result
- 클리어하면 다음 스테이지가 열린다(`unlocked = max(unlocked, stageId + 1)`, 최대 10). 별·점수는 더 큰 값만 남는다
- 지도로 돌아왔을 때 **방금 열린 스테이지**는 노드가 한 번 크게 튀어나오는 연출 (`StageMap`이 직전 unlocked를 기억해 비교, 세션 안에서만)
- 확인: 1번 클리어 → 지도에서 2번 열림 → 새로고침해도 유지
